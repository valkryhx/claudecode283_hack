# 20261024-CC 输入框看图链路实现调研（Claude Code 2.1.303）

> 范围：用户在输入框粘贴 / 拖入 / 打出图片路径 → 提交 → 变成原生 image content block 的**完整链路**。
> 不含 Read 工具读图（那条见 `docs/20261024-CC-view-image实现调研.md` §2）。
> 所有结论带 `模块:行号`，模块位于 `reconstructed303/deminified/`。
> 产物是 **Windows 构建**，剪贴板命令走 PowerShell 分支；文中同时记录 darwin/linux 定义，供跨平台复刻参考。

---

## 0. 结论先行

1. **输入框不是"粘贴图片"，是一个粘贴事件分流器**：空粘贴 → 读剪贴板图；文本里是图片路径 → 读文件；其余 → 普通文本。
2. **三种触发**：真实 paste 事件、单次按键内容 > 800 字符（终端把粘贴当按键送进来）、空粘贴且平台是 macOS/WSL。
3. **剪贴板图先落临时 PNG**，再走与 Read 工具**同一套**预算管线；BMP 在内存里转 PNG，临时文件用完即删。
4. **路径粘贴一次可以多个**，按"空格后跟 `/` 或盘符"和换行切分；非图片部分原样回填到输入框。
5. **读路径有权限门**：返回 `refused` / `unexamined`，被拒绝时**退回文本粘贴**而不是报错吞掉。
6. **校验三重**：扩展名白名单 → 文件内容 magic bytes → 尺寸/字节预算；任一步失败都只影响这一张图。
7. **附件是内存 store**：`{id, type:"image", content, mediaType, filename, dimensions, sourcePath}`，输入框里显示 `[Image #N]`。
8. **删占位符即删附件**（`Ac`）；未提交的草稿 90 秒回收。
9. **提交时两条来源合流**：直接 image blocks + 粘贴 store 里的 base64，统一走同一个归一化函数。
10. **同时把图写进磁盘 image store**（`<id>.<ext>`，0600，`wx`，200 条 LRU），供 transcript / 可点击链接引用。
11. **最终消息**：`user.content = [text, image...]`，带 `imagePasteIds`；尺寸说明**另发一条** `isMeta + turnCompanion` 消息。
12. **占位符不剥离**：`[Image #N]` 原样发给模型，靠 image block 与顺序对齐。

## 2. 粘贴识别：`Ant` 分流器

组件签名（`m0845_0xf76ba90.js:59`）：

```js
function Ant({ onPaste, handleKeyDown, onImagePaste })
```

它不渲染任何东西，只把"输入事件"翻译成三种结果：普通文本、图片附件、被回填的文本。

### 2.1 三种触发

| 触发 | 判定 | 行为 |
|------|------|------|
| 真实 paste | `handlePaste`（`:189`） | `preventDefault` → `L(text, rawEmpty, rawEndedWithFocusTail)` |
| 终端把粘贴当按键 | `handleKeyDown_2`（`:192`）：`!ctrl && !meta && key.length > VY` | 同样进 `L(...)` |
| 空粘贴 | `L` 内 `K && (macOS || WSL) && onImagePaste` | 调防抖后的剪贴板读图 |

`VY = 800`（`m0549:26`）是"一次按键内容超过 800 字符就当粘贴"的阈值。
`dr = 50`（`m0845:55`）是剪贴板读图的防抖窗口（`F$(ne, 50)`）。

### 2.2 `L` 的完整分流（`m0845:141`）

```js
function L(O, K = O.length === 0, te = O.endsWith("[I") || O.endsWith("[O")) {
  S.current = true;                        // 标记"正在粘贴"
  let Q = te ? O.replace(/\[[IO]$/, "") : O;   // 去掉终端焦点上报尾巴
  if (K && (isMacOS || isWSL) && onImagePaste) { debouncedClipboardPaste(); return; }
  let oe = Q.split(/ (?=\/|[A-Za-z]:\)/).flatMap(s => s.split("\n")).filter(s => s.trim());
  let M = [], Y = [];
  for (let j of oe) if (Pds(j)) M.push(j); else Y.push(j);
  ...
}
```

要点：

1. **先剥 `[I` / `[O`**：终端 focus reporting 会把 `ESC[I` / `ESC[O` 混进粘贴内容。
2. **切分规则**：只在"空格后紧跟 `/` 或 `X:\`"处切，再按换行切；避免把普通句子拆开。
3. **`Pds` 只判扩展名**（见 §4.1），不碰文件系统。
4. 图片段进 `M`，其余进 `Y`；处理成功后 `Y.join("\n")` 原样回填输入框（`:170`）。

### 2.3 多图读取与手势

```js
Promise.all(M.map(item => Ods(item, Ct(), permissionAwareRead)))
```

- `Ct()`（`m0549:56`）取当前模型的图片 limits。
- 第三个参数是**权限感知读**（`X8s`，`m0459:59247`），不是裸 `readFile`。
- 结果数组里可能含 `"refused"` 字符串，用来区分"权限拒绝"与"读失败"。
- 每张图回调 `onImagePaste(base64, {...})`，带 `continuesGesture: index > 0`，
  让 UI 把同一次拖拽/粘贴产生的多张图当成一个手势（撤销/展示分组）。

### 2.4 失败时的三条退路

| 情况 | 行为 | 遥测 |
|------|------|------|
| 部分图读失败，但至少一张成功 | 成功的进附件，剩余文本回填 | — |
| macOS 截图临时路径（`/TemporaryItems/.../screencaptureui.../Screenshot`）且路径全为绝对路径 | 退回**剪贴板读图**（`U()`） | — |
| 权限拒绝 / 读取失败 | 整段原文回填为文本 | `input_image_drag` + `read_withheld` / `read_failed` |
| 抛异常 | 原文回填 + toast | `input_image_drag` + `read_threw` |

**关键设计**：任何图片失败都**不阻断输入**——最坏情况退化成"用户贴了一段路径文本"。

### 2.5 粘贴中按回车：先排队，后自动提交

```js
if (S.current && O.name === "return") { O.preventDefault(); T.current = true; return; }
```

粘贴还在异步读图时按回车，不会丢：`T.current` 记下意图，
读图完成后的 `setTimeout(0)` 里合成一次 return（`q()`），自动提交。

## 3. 剪贴板读图：`mue`

### 3.1 平台命令表（`m0549:32` `B()`）

| 平台 | checkImage | saveImage | 读文本路径 | 删除 |
|------|-----------|-----------|-----------|------|
| win32 | PowerShell `-Sta` + `System.Windows.Forms.Clipboard::ContainsImage()` | 同左 + `GetImage().Save(path, Png)` | `powershell -NoProfile -Command Get-Clipboard` | `Remove-Item -LiteralPath` |
| darwin | `osascript -e 'the clipboard as «class PNGf»'` | osascript 写文件 | `osascript ... the clipboard as «class furl»` | `rm -f` |
| linux | `xclip -t TARGETS -o \| grep image/...`（或 `wl-paste -l`） | `xclip -t image/png -o > file`（或 bmp / wl-paste） | `xclip -t text/plain -o`（或 `wl-paste`） | `rm -f` |

本 303 产物是 Windows 构建，`commands` 取 `y.win32 || y.linux`（`:75`），即 PowerShell 分支。

### 3.2 临时文件

`screenshotPath = <temp>/claude_cli_latest_screenshot.png`（`:34-38`），
temp 目录可被 `CLAUDE_CODE_TMPDIR` 覆盖（`:41` 的提示串）。
每次读图前 `mkdir(dir, {mode: 0o700})`，读完 `deleteFile`。

### 3.3 读取流程（`m0549:85`）

```text
checkImage 退出码 != 0  → 返回 null（剪贴板没有图）
saveImage  退出码 != 0  → 遥测 save_failed，返回 null
readFileBytes
  └ 前两字节是 "BM" → sharp().png()   // BMP 在内存里转 PNG
K8e(buffer, len, "png", limits, {directWebpMaxBytes})   // 与 Read 工具同一预算管线
base64 → sft(base64) 嗅探真实 mediaType
deleteFile
return { base64, mediaType, dimensions }
```

注意：**剪贴板读图不经过扩展名校验**，因为来源就是像素；媒体类型由 base64 头部嗅探（`sft`）决定。

### 3.4 遥测与降级

- `clipboard_read` 成功；
- `clipboard_read` + `construct_failed` / `save_failed` / `read_failed`；
- 上层 `input_image_paste` + `clipboard_read_failed`（`m0845:101`）。

任何一步失败都返回 `null`，上层静默退回普通粘贴——**不会弹错误框打断输入**。

## 4. 路径粘贴

### 4.1 判定：只认扩展名

```js
var WRt = /\.(png|jpe?g|gif|webp)$/i;   // m0549:129
function Pds(e) {                        // :138
  let s = P(e.trim());                   // 去掉成对引号
  return WRt.test(s);
}
```

- **不含 `.bmp`**：路径粘贴不接受 BMP（但剪贴板与 Read 工具接受，见 §3.3 与 Read 调研）。
- 引号剥离只处理"首尾都是 `"` 或都是 `'`"的情况（`:130`）。
- 扩展名只是"是否进入图片分支"的判据，**内容仍要二次校验**（§4.4）。

### 4.2 WSL 路径

```js
var S = /^(?:[A-Za-z]:\|\\)/;          // :134，Windows 盘符或 UNC
if (isWSL() && S.test(path)) path = await new WslPath(process.env.WSL_DISTRO_NAME).toLocalPath(path);
```

在 WSL 里贴 `C:\Users\...\a.png`，会先转成 `/mnt/c/...` 再读。

### 4.3 绝对路径与"同名文件"回退

```js
if (isAbsolute(path)) bytes = await permissionAwareRead(path);
else {
  let clip = await readClipboardText();      // m0549:117
  if (clip && path === basename(clip)) bytes = await permissionAwareRead(clip);
}
```

用户复制文件管理器里的**文件名**（而不是完整路径）时，用剪贴板里的绝对路径补齐。
这是 Windows 资源管理器"复制文件"的常见形态。

### 4.4 读取与校验（`m0549:149` `Ods`）

```text
_oo(path)                        扩展名不符 → null
WSL 转换
绝对路径 → 权限感知读；否则用剪贴板路径补齐
  ├ "refused"                     → 返回 "refused"
  ├ null / "absent" / 空文件      → null（空文件额外 warn）
  ├ 前两字节 "BM"                 → sharp().png()
  ├ Ih(bytes) magic 校验失败      → warn + null
  └ K8e(bytes, len, subtype, limits)
return { path, base64, mediaType: `image/${...}`, dimensions }
```

**双重校验**：扩展名决定"要不要试"，magic bytes 决定"是不是真的图"。
扩展名对但内容不是图（比如 `.png` 其实是 HTML）会被拒绝并给出可读警告：

```text
Pasted path has image extension but content is not a supported image: <path>
```

### 4.5 权限门（`m0459:59234` `VWt` / `:59247` `X8s`）

粘贴路径的读取**不是裸 `fs.readFile`**：

1. 先取当前权限规则集；
2. deny 规则命中 / 规则集为空 → `"refused"`；
3. 符号链接且没有允许规则 → `"unexamined"`；
4. 否则解析 realpath，用同一批规则**再核一遍**；
5. 通过 → `"unexamined"`（继续读）；否则 `"refused"`。

`X8s` 把结果映射成：`refused` → 返回字符串 `"refused"`；`unexamined` → `readFileBytes`；
其余 → 带权限作用域的读（`KWt`）。上层据此区分"权限拒绝"与"读失败"。

### 4.6 失败分类

| 结果 | 上层处理 |
|------|----------|
| `"refused"` | 原文回填；遥测 `read_withheld` |
| `null`（不存在/空/非图） | 原文回填；遥测 `read_failed` |
| 抛异常 | 原文回填 + toast；遥测 `read_threw` |
| 部分成功 | 成功的进附件，失败段作为文本回填 |

**没有一种失败会让输入框变空或弹模态框。**

## 5. 附件 store 与占位符

### 5.1 铸造：`bs`（`m0863:2144`）

```js
function bs(store, insert, { onMinted }) {
  return (content, meta) => {
    let id = mintId(store);
    onMinted?.(id);
    store[id] = {
      id, type: "image", content,          // base64
      mediaType: meta?.mediaType ?? "image/png",
      filename: meta?.filename,
      dimensions: meta?.dimensions,
      sourcePath: meta?.sourcePath,
    };
    insert(new PasteText(`[Image #${id}] `));   // 占位符 + 空格
  };
}
```

- 条目里**同时有 base64 和 sourcePath**：base64 用于提交，path 用于展示/落盘/追溯。
- 插入的是纯文本占位符，不是富文本芯片对象。

### 5.2 占位符格式（`m0353:1396`）

```js
function K9(e) { return `[Image #${e}]`; }
```

解析用同一模块的全局正则（`m0353:1040`）：

```js
regExp = /\[(Image|Pasted text) #(\d+)(?: \+\d+ lines)?(\.)*\]/g
```

即图片与长文本粘贴共用一套编号空间。

### 5.3 剪枝：删占位符 = 删附件（`m0863:2132` `Ac`）

```js
function Ac(store, messages, { pruneTextPastes = false } = {}) {
  let alive = new Set();
  for (let m of messages) for (let p of parsePlaceholders(m)) alive.add(p.id);
  for (let item of Object.values(store))
    if ((pruneTextPastes || item.type === "image") && !alive.has(item.id)) delete store[item.id];
}
```

用户把 `[Image #3]` 从输入框删掉，对应的 base64 就不会被提交——
**附件生命周期完全由文本占位符驱动**。

### 5.4 草稿回收（`m0863:2161`）

`ph = 90000`（90s）、`fh = 45000`（45s）：草稿条目在"观察不到"累计 90 秒后删除，
扫描间隔上限 45 秒。避免切换会话后图片长期占内存。

### 5.5 渲染：可点击的 `[Image #N]`

`m1556:4532` / `m1374:1213` 把占位符渲染成终端超链接：

```js
children = imageId ? `[Image #${imageId}]` : "[Image]";
url = storedImagePaths.get(imageId);      // 磁盘 image store 的路径
// 支持 OSC-8 的终端里 → 可点击打开；否则退化为纯文本
```

### 5.6 历史里的粘贴内容

提示词历史（上下键召回）对粘贴内容做分流（`m0353:2038`）：

- `content.length <= 1024` → 直接内联；
- 否则只存 `contentHash`，召回时再取。

这解释了为什么粘贴条目 schema 里同时有 `content` 和 `contentHash`（`m0353:1381`）。

## 6. 提交：`Ln` 如何把附件变成消息

`Ln`（`m0683:2352`）是"用户输入 → 消息"的总装线，参数很多，图片只占其中一段（`:2377-2455`）。

### 6.1 两种输入形态

```js
if (typeof e === "string") inputString = e;
else if (e.length > 0) {            // e 已经是 content block 数组
  for (let B of e) {
    if (B.type !== "image") { x.push(B); continue; }
    let N = await lLt(B, limits);   // 归一化：校验 + 缩放
    x.push(N.block);
    if (N.block.type !== "image") continue;   // 降级成文本
    ...
  }
}
```

- **形态 A**：普通文本（`string`），图片只可能来自 `pastedContents`。
- **形态 B**：调用方直接传 blocks（例如从桥接/队列回放），图片先过 `lLt`。

### 6.2 `lLt`：base64 block 的守门员（`m0396:813`）

```text
source 不是对象 / type !== "base64"     → 原样返回或降级文本
media_type 不是字符串                   → 降级文本
Buffer.from(data, "base64") 失败        → 降级文本
否则 → jb({data, mediaType, limits})
```

降级文本固定为：

```text
[Image could not be processed: <reason>]
```

并记 `tengu_image_resize_degraded`。**坏图不会让整条消息失败，只会变成一行文本。**

### 6.3 `jb`：base64 进、预算后的 block 出（`m0396:609`）

与剪贴板、路径粘贴共用同一条管线：

```text
metadata()
  ├ 格式不在支持集 → 转 png（必要时先试 webp）
  ├ 尺寸未知 → 用 magic 读；仍未知且超 API 上限 → 抛错
  ├ 原始字节 <= targetRawSize 且无需缩放 → 直接返回
  ├ 需要缩放 → Y(w,h,limits) 二分求最大合规尺寸
  ├ png 优先（compressionLevel 9, palette）
  ├ 仍超 → jpeg 80/60/40/20 逐级
  └ 仍超 → 缩到 1000 宽 + jpeg q20
返回 { buffer, mediaType, dimensions:{originalWidth, originalHeight, displayWidth, displayHeight} }
```

### 6.4 `NXo`：落盘 image store（`m0681:114`）

```js
let G = await NXo({ ...pastedContents, ...inlineImages }, setStoredImagePaths);
```

- 目录：`D()`（`m0681:64`）；某些认证模式下 `LXo()` 为 false，直接禁用落盘。
- 文件名：`<id>.<ext>`，扩展名由 base64 头部嗅探（`sft(content.slice(0, 64))`）。
- 写入：`open(path, "wx", 0o600)` → write(base64) → datasync → rename 原子替换；
  已存在则先删再 rename，并 `recheckBeforeWrite`。
- 上限：`fe = 200` 条 LRU（`m0681:62`、`:167`）。
- 返回值 `Map<id, path>` 同时写进 app state 的 `storedImagePaths`，供输入框渲染可点击链接。

### 6.5 `Lee`：尺寸说明（`m0396:993`）

只有"被缩放过"或"有源路径"才生成说明：

```text
[Image: source: <path>, original 3024x1964, displayed at 1568x1018.
        Multiply coordinates by 1.93 to map to original image.]
```

- 无尺寸但有路径 → `[Image source: <path>]`
- 既没缩放也没路径 → **不生成**（避免噪音）

这条说明**不塞进 user 消息**，而是由 `gs` 追加成独立消息（§6.6）。

### 6.6 最终消息结构

```js
// m0683:2668
let Qe = gs({
  ...lr(R ?? te, Ce, ie, he, ...),   // user message
}, Be);                              // 尺寸说明数组
```

`lr`（`m0683:1642`）产出：

```js
{
  type: "user",
  content: [ {type:"text", text:"..."}, {type:"image", source:{...}}, ... ],
  imagePasteIds: [3, 4],      // 本次消息引用了哪些粘贴条目
  uuid, promptId, origin, permissionMode, ...
}
```

`gs`（`m0683:2737`）产出：

```js
{
  type: "user",
  isMeta: true,
  turnCompanion: true,
  content: [ {type:"text", text:"[Image: source: ...]"}, ... ]
}
```

**两条消息**：主消息带图，meta 消息带尺寸/路径说明。
模型看到的顺序是"图 + 文本"，然后紧跟一条系统性质的说明，不会把说明当成用户要求。

### 6.7 占位符不剥离

`Ln` 全程没有删除 `[Image #N]`；`content` 就是用户输入的原文（`text_2`）。
模型看到的是：

```text
看下这个 [Image #1] 报错
[image block]
```

顺序对齐靠 `imagePasteIds` 与 block 顺序，而不是把占位符替换成别的东西。

## 8. 旁路：另外四条进图通道

输入框主链路之外，CC 还有四条"图片进入会话"的路径，它们共用同一套 `jb` 归一化与 `image` block 结构，但触发方式不同。

### 8.1 拖拽文件（drag & drop）

`m1837:868-878` 的提示文案明确列了两种方式：

```text
• drag and drop image files into the terminal
• Paste images from clipboard with <shortcut>
```

拖拽在终端里表现为"一串带引号的路径被粘贴进来"，因此走的是 §4 的路径粘贴分支，不是独立的 DnD 解析器。
这也解释了 `P()`（`m0549:130`）为什么要剥引号——终端拖拽给的就是带引号路径。

### 8.2 Read 工具读图（agent 自主读）

由工具调用触发，与输入框无关：

- 权限门 `VWt`（`m0459:59234`）→ 校验 → `X8s`（`:59247`）读文件
- 走 `m0086:388-391` 的预算：2000x2000 / 5 MiB base64 / 3.75 MiB targetRawSize
- 输出为 `tool_result.content` 数组里的 image block

> 这条链路与 GA 的"agent 自主读图"需求对应，详见 `docs/20261024-CC-view-image实现调研.md`。

### 8.3 `edited_image_file`

`m0459:178382` 出现 `edited_image_file`，用于图片被外部编辑器改过之后重新入会话。
它不改消息结构，只是把"同一 id 的图"换成新内容——等价于附件 store 的一次更新。

### 8.4 `inlined_image_paths`

`m0683:2568` 在消息 meta 里记录 `inlined_image_paths`：本次消息中"由路径自动转成图"的那些路径。
用途是让 UI / 遥测知道哪些图是用户显式给的、哪些是路径推断来的，**不影响模型看到的内容**。

### 8.5 入口对照表

| 入口 | 触发 | 是否过 `jb` | 是否落 image store | 消息里的形态 |
|------|------|------------|-------------------|-------------|
| 剪贴板粘贴 | 快捷键 / 图片粘贴 | 是 | 是（`NXo`） | image block + 占位符文本 |
| 路径粘贴 | 粘贴路径字符串 | 是 | 是 | image block + 原路径文本 |
| 拖拽文件 | 终端 DnD | 是（走路径分支） | 是 | 同上 |
| Read 工具 | 模型调用 | 是 | 否 | `tool_result` 内 image block |
| 外部编辑回写 | `edited_image_file` | 是 | 是（更新） | 替换已有 block |

## 9. 可复刻清单

按"复刻一条输入框看图链路最少需要什么"排序。每条都标了 CC 的做法与可省略的部分。

### 9.1 必须有

1. **粘贴事件分流**
   - 短文本走正常输入；长文本 / 图片 / 路径走附件
   - 判据：`key.length > 800` 或 `clipboard has image` 或 `路径命中扩展名`
   - CC 用 `Ant`（`m0845:59`）统一收口，三条退路（`onPaste` / `onImagePaste` / `handleKeyDown`）

2. **剪贴板读图（按平台分支）**
   - win32：PowerShell `-Sta` + `System.Windows.Forms.Clipboard`
   - darwin：`osascript` + `«class PNGf»`
   - linux：`xclip` / `wl-paste`
   - 统一写临时文件再读字节，避免 shell 转义问题

3. **统一归一化**
   - 一个函数（CC 是 `jb`）负责：格式嗅探 → 缩放 → 重编码 → 返回 `{buffer, mediaType, dimensions}`
   - **所有入口都必须过它**，否则会出现"粘贴能看、路径不能看"的割裂

4. **附件 store**
   - `id` 单调递增，`[Image #N]` 与 `id` 一一对应
   - 落盘用原子写 + `0600`
   - 有条数上限（CC 是 200）与草稿 GC（90s / 45s）

5. **消息组装**
   - 主消息：`content` 数组 = 文本 + image block，顺序与占位符出现顺序一致
   - 附一条 `isMeta` 消息放尺寸/路径说明，避免污染用户意图

6. **失败降级**
   - 单图失败 → `[Image could not be processed: <reason>]` 文本，不阻断整条消息
   - 格式不支持 → 先尝试转 png，再失败才降级

### 9.2 建议有

7. **权限门**：读本地路径前校验，区分"拒绝"与"未检查"
8. **尺寸说明**：只有缩放或带路径时才加，避免噪音
9. **磁盘链接渲染**：UI 侧把 `[Image #N]` 渲染成可点击的 OSC-8 链接
10. **占位符不剥离**：保留原文，靠 `imagePasteIds` 对齐，模型更容易理解上下文

### 9.3 可以简化

11. 多平台剪贴板命令表：只支持当前平台即可
12. 遥测事件（`tengu_*`）：可省略
13. WSL 路径转换：非 WSL 环境可省略
14. 草稿 GC 双阈值：单阈值即可

### 9.4 常见坑

| 坑 | 后果 | CC 的解法 |
|----|------|----------|
| 只处理剪贴板，不处理路径 | 用户粘路径没反应 | 路径分支 + 扩展名判定 |
| 扩展名白名单漏 bmp | bmp 粘贴失败 | 剪贴板走 magic 嗅探，扩展名只管路径 |
| 每个入口各自缩放 | 同一张图尺寸不一致 | 统一 `jb` |
| 占位符被替换成别的文本 | 模型对不上图 | 保留原文 + `imagePasteIds` |
| 说明文本塞进 user 消息 | 模型把说明当指令 | 独立 `isMeta` 消息 |
| 坏图抛异常 | 整条消息发不出 | 降级成文本 |
| 临时文件不清理 | 磁盘堆积 | 落 store 后删临时文件 |
| 大图不缩放 | 超 API 上限被拒 | 长边 1568 + 质量阶梯 |

## 11. 一句话总结

CC 的输入框看图链路是**"三条入口（剪贴板 / 路径 / 拖拽）+ 一个归一化函数（`jb`）+ 一个附件 store + 两条消息（正文带图、meta 带说明）"**：

- 入口分得细，但归一化和落盘只有一份，所以三条入口行为一致；
- 占位符 `[Image #N]` 只做 UI 锚点，不参与内容替换，模型看到的是"原文 + image block"；
- 失败一律降级成一行文本，任何一张坏图都不会让整条消息发不出去；
- 尺寸/路径说明走独立 `isMeta` 消息，不污染用户指令。

这三条设计（统一归一化、占位符不剥离、失败降级）是最值得照搬的部分。
