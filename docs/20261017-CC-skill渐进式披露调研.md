# CC v2.1.283 Skill「渐进式披露」源码调研

> 输入物：`claudecode283/claude.exe`（v2.1.283）抠出的明文 JS 模块 `claudecode283/modules/`。
> 本文所有结论均给出模块 + 符号 + 原文片段，可逐条回查。
> 面向：把 CC 的 skill 机制复刻进自研 agent（GA）。

---

## 0. 一句话结论

CC 的 skill 是**三级披露**，且「披露」的粒度由 **skill 作者**决定：

| 级别 | 进上下文时机 | 内容 | 成本 |
| --- | --- | --- | --- |
| **L1 清单** | 每轮都在 | 名字 + 一行描述（+ when_to_use） | 常驻，有字符预算 |
| **L2 正文** | 调用 Skill 工具那一刻 | SKILL.md 全文 | 仅调用时 |
| **L3 附带文件** | 模型自己按需 Read | skill 目录里的 `references/`、脚本等 | 仅需要时 |

重要认知（易错）：CC **不是**把 SKILL.md 切成多段按需加载——L2 也是**载入全文**
（`m1918` 的 `onInvoke: content.trim()`）。渐进披露的真正杠杆是 ①清单常驻 ②**正文本身要瘦**，
重内容挪到附带文件（L3）。

## 1. L1：常驻清单（listing）

### 1.1 注入点与模板
`m0357_0xc63ba04.js` 的提醒构造表里：

```js
skill_listing:(e)=>{ if(!e.content) return [];
  return xi([Ce({content:"The following skills are available for use with the Skill tool:" + 空行 + e.content, isMeta:!0})]) },
dynamic_skill:(e)=>{ ... "New skills discovered in " + s + ", now available via the Skill tool:" + 仅名字列表 ... },
```

- `isMeta:!0` → 这是**系统提醒**，不进对话正文。
- `dynamic_skill`：新发现的 skill 也只播报**名字**，不播报正文。

### 1.2 每行格式
`m0357`：
```js
function prt(e){ return e.whenToUse ? (e.description + " - " + e.whenToUse) : e.description }
function FYo(e){ return "- " + e.name + ": " + NYo(e) }          // 列表行
function NYo(e){ let n=prt(e), r=urt(); return n.length>r ? n.slice(0,r-1)+"…" : n }  // 按上限截断
```
- 行格式：`- <name>: <description> - <when_to_use>`
- 单条描述上限：`urt()` = `skillListingMaxDescChars ?? ZXn`，**`ZXn = 1536`**（字）
- 用于 token 计量的 always-on 文本：`function jwr(e){ return [e.name,e.description,e.whenToUse].filter(Boolean).join(" ") }`

### 1.3 字符预算与降级
`m0357`：
```js
QXn=0.01, mSt=4, JXn=200000;
function e7n(){ return Je().skillListingBudgetFraction ?? QXn }
function EVe(e,n=mSt){ let r=WD(process.env.SLASH_COMMAND_TOOL_CHAR_BUDGET); if(r) return r;
  let s=e7n(), g=(e??JXn)*n*s; return Math.max(1, Math.floor(g)) }
```
→ 预算 = `上下文窗口 × 4 × skillListingBudgetFraction(默认 0.01)`，200k 上下文时 ≈ **8000 字**；
env `SLASH_COMMAND_TOOL_CHAR_BUDGET` 可整体覆盖。

`Fqt(...)` 的降级策略（超预算时）：
1. 打印 warn：`Skill listing over budget: N skills, X chars > Y budget — descriptions will be truncated. Run /skills to disable some, or raise skillListingBudgetFraction in settings.`
2. **bundled** 来源的 skill 直接降为 `- <name>`（无描述）
3. 其余按 `n(...)` 排序，逐条尝试保留完整描述，塞不下的降为 `- <name>`
4. 结果：清单永远是「`- name: desc` 与 `- name` 混排」，**永不超预算**

### 1.4 目录作用域 skill 的命名
`m0357`：
```js
function wF(e,n){ return e + ":" + n }                 // "apps/web:deploy"
function IYo(e,n,r){ ... name:(e+":"+n), description:(e.description + " (scoped to " + n + "/ — use this instead of the unscoped \"" + e.name + "\" skill when the files being changed are under " + n + "/)") }
```
→ 同一名字的「目录作用域版」与「无作用域版」共存时，**按正在改的文件路径选最具体的一个**。

### 1.5 `/skills` 菜单里的原文解释（`m0898_0xd16525c.js`）
```text
context = this skill's one-line listing in the system prompt, included every turn
(dash = not in the current listing, costs nothing; full SKILL.md loads only when it runs)
```
这两行就是 CC 自己对渐进披露的官方表述。

## 2. L2：调用时加载正文

### 2.1 Skill 工具描述（`m0357`，常量 `Nqt`）
```text
Invoke a skill.

A skill is a packaged set of instructions the user or project has set up for a particular kind of task
(deploy steps, a review checklist, a repo-specific workflow). Available skills appear in a system-reminder
listing with one-line descriptions. When the task at hand is one a listed skill covers, call this tool first
— the skill's instructions load into the turn for you to follow in place of your default approach; some skills
instead run in a subagent and return the finished result. ...

- `skill`: exact name from the listing, no leading slash. Plugin skills use `plugin:skill`. Directory-scoped
  skills are listed with a path prefix (`apps/web:deploy`); ...
- `args`: optional arguments to pass through.

Only names from the listing (or that the user typed explicitly) are valid. ...
If a `<...>` block is already present this turn, the skill is loaded — follow it directly rather than calling again.
```
另有**协调者会话**变体 `$Yo`：协调者自己调用是**只读**（只加载指令用于判断/协调，不执行），
执行交给 worker。

### 2.2 加载产物：alwaysOn vs onInvoke（`m1918_0xe1e085b.js`）
```js

async function w(n,e){                  // n=SKILL.md 路径, e=skill 名

  let c = s.when_to_use!=null ? String(s.when_to_use) : void 0;

```
- **`alwaysOn`** = `name description whenToUse`（进 L1 清单）
- **`onInvoke`** = SKILL.md 正文全文（L2）
- `ms(...)` = frontmatter 解析（`normalizeKeys:true`）
- `S(...)` 给每个 skill 附 `chars:{always_on, on_invoke}`（供 `/skills` 计量）

→ 两种布局都支持：`<skills>/<name>/SKILL.md` 与 `<skills>/SKILL.md`；名字优先取 frontmatter `name`。

## 3. L3：附带文件按需读

- skill 目录里可以放任意文件；正文里指向它们，模型**需要时用 Read 读**，不预加载。
- 证据一：`/skills` 菜单原文（§1.5）——"full SKILL.md loads only when it runs"。
- 证据二：`m1556_0xdcb6d73.js` 的 `propose_skills` 工具，读写 `skillRoot` + `SKILL.md`：
  `"A saved proposal replaces a skill's SKILL.md entirely — read that whole file first, then propose the complete updated SKILL.md."`
  （说明 SKILL.md 是"唯一入口文档"，其余文件是它的附属）。
- 证据三：内置打包 skill 带**文件清单**。`m1635_0xddbbc29.js`：
  ```js
  ye = {"storybook/SKILL.md":a, "non-storybook/SKILL.md":o, "package-build.mjs":e(R),
        "lib/common.mjs":..., "lib/detect.mjs":..., ...}
  export { ye as SKILL_FILES, ue as SKILL_MD }
  ```
  → 一个 skill 可以带 `SKILL.md` + 若干 `lib/*.mjs` + 入口脚本，正文按需引用。

## 5. 复刻要点清单（给自研 agent）

1. **L1 清单**：名字 + 一行描述（+ when_to_use）；给**字符预算**（建议按上下文比例，或固定 8000）；
   超预算**降级为 `- name`**，绝不超预算。
2. **L2**：只有调用 Skill 工具时才载入正文；正文**第一行给 base dir**（L3 要用）。
3. **L3**：正文**必须瘦**——细节放 `references/*.md`，正文只写"需要 X 时读 references/x.md"。
4. **压缩后回注**：compact 后把已调用 skill 的**清单行 + 摘要**重新注入（不要注入全文，也不要当成新请求）。
5. 可选：`name-only` / `disable-model-invocation` / `user-invocable` / `allowed-tools` 覆盖。

## 7. 追加实证：Workflow 的 17K authoring prompt 到底怎么加载（2026-10-17 复核）

> 这一节回答两个容易混淆的问题：
> 1. CC 的 Workflow authoring reference（约 17.5K 字符）是不是“一次性塞进工具描述/上下文”？
> 2. 为什么它可以作为 `isMeta` user message 注入当轮，而不像 GA 那样把 17.7KB 塞进 `tool_result` 后触发渠道 guardrail？

### 7.1 结论先说

**主路径不是一次性常驻，而是“3KB 工具描述 + 按需 load skill”；17.5K 正文只在 Skill 被调用时加载一次。**
当 skill 系统不可用时，CC 才把同一份 17.5K 正文**内联回退**到 Workflow 工具描述里。

| 路径 | Workflow 工具描述 | 17.5K 正文位置 | 触发条件 |
| --- | --- | --- | --- |
| 主路径（skill 可用） | 约 3,078 字符 `t` + 185 字符 `i` 指针 | Skill 调用后，作为独立 `isMeta` user message | `fSe(tools) === true` |
| 回退路径（skill 不可用） | `t + Anr()`，约 20,604 字符 | 直接内联在 Workflow 工具描述 | `fSe(tools) === false` |

所以“CC 上下文大所以可以一次塞 17K”不是核心原因。**核心是：17K 正文被设计成按需加载，而且走独立消息通道，不塞进 tool_result。**

### 7.2 源码坐标：两档描述如何选择

`m1502_0xdb4a986.js`：

```js

  ... 完整 authoring reference ...
```

实测尺寸：

- `t`：**3,078 字符**；
- `i`：**185 字符**；
- `Anr()`：**17,526 字符**；
- `t + i`：约 **3,263 字符**（主路径工具描述）；
- `t + Anr()`：约 **20,604 字符**（回退路径工具描述）。

Workflow 工具本身（`m1569_0xdceb889.js`）调用：

### 7.3 17.5K 正文的真实来源：内置 skill，不是额外文件

`m1503_0xdb4fec6.js` 把 `Anr()` 注册成内置 `workflow-authoring` skill：

因此主路径的 17.5K 正文 = **Skill 工具调用后，由这个内置 skill 返回的 `Anr()`**。
它不是在 Workflow 工具 schema 里常驻，而是 `load skill` 时才进入本轮。

它之所以不出问题，是因为：

2. 17.5K 正文是普通 user text，不是嵌套在 tool_result JSON 里的巨型字符串；
3. 正文只在调用 Skill 时加载，不常驻、不每轮重复；
4. 字节级重复调用会被去重/替换成短提醒；
5. 压缩后若旧正文被截断，重调用时会先加一条“之前加载的副本被 compaction 截断，完整指令随后”的 `isMeta` 提示。

### 7.6 与 GA 的差异（关键）

| 维度 | CC 主路径 | GA 当前 |
| --- | --- | --- |
| Workflow 工具描述 | 约 3.3K 字符，只提示 load skill | GA 已有类似短提示 |
| skill 正文通道 | 独立 `isMeta` user message | `load_skill` 返回 dict，正文在 `tool_result` JSON 里 |
| tool_result 体积 | 约 30-40 字符确认 | 17.7KB 正文 |
| 正文加载 | 按需、一次、可去重 | 按需，但每次都作为大 tool_result |
| 回退 | skill 不可用时才内联 17.5K | 无同等“回退内联”设计，因为 GA 总是走 load_skill |

**因此 GA 要抄的不是“把 17K 分成很多段”，而是：**

1. 保持 Workflow 工具描述短，只指向 `load_skill`；
2. 让 `load_skill` 的工具结果只做“已加载”确认；
3. 把 skill 正文作为**独立注入消息**（GA 当前可先做成 `next_prompt` / 下一轮 system/meta 注入，不必先改 API 协议）；
4. 正文本身瘦身，重内容放 `references/`；
5. 重复加载同一 skill 时去重；
6. compact/续跑后做 `invoked_skills` 回注。

> 复刻边界：本节只讨论本地 Skill/Workflow 加载链。
> **【复刻时暂时不需要参考 claudecode 云端会话的实现】**
