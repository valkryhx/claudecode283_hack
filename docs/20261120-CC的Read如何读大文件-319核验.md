# CC 的 Read 怎么读大文件、为什么不会被读前置卡住（319 源码核验）

日期：2026-11-20
结论依据：`reconstructed319/deminified/` 逐行 + 提示词快照
可复算：`docs/probes/20261120-CCRead大文件机制核验.py`（9 项断言）

## 0. 一句话结论

**CC 从来没有「必须完整读过才能覆盖写」这条规则。** 它只要求「touch 过」。
Hlaudz 旧实现凭空加了一条 CC 不存在的规则，还用一个**必然失败**的判据
去实现它 —— 这是真正的 bug，不是「门槛严一点」。

## 1. 回答第一个问题：Read 有行数参数吗？

有。`offset` + `limit`。

| 事实 | 坐标 |
| --- | --- |
| 默认 **2000 行** | `m0274_0x117329cf.js:604` `$tn = 2000` |
| 提示词也这么写 | `claude-code-fable-5.2.md:2331` "Reads up to 2000 lines by default" |

⚠️ **Hlaudz 是 `DEFAULT_READ_LINES = 200`** —— 差 10 倍。这个差异本身
不致命（见下），但它让「读全」在实践上更难达成。

## 2. 超过默认行数时发生什么？

不是拒绝，是**分页 + 明确告知下一页怎么读**（`m0591:148116`）：

```
[Truncated: PARTIAL view — <file>: showing lines 1-N of M total
(T tokens, cap G). Call <Read> with offset=N+1 limit=N for the next page,
or <Grep> to find a specific section. Do NOT answer from this page alone
if the answer may be further in the file.]
```

三件事同时做了：① 截断；② 告诉模型**怎么翻页**；③ 告诉模型**别只看这页就下结论**。

还有一条兜底路径：当文件是「超长行、无法按行分页」时，退化成按字符截断，
并且**按 UTF-16 代理对边界修正**（`m0591:148114` `if (hr >= 55296 && hr <= 56319) qo = qo.slice(0, -1)`）——
避免把一个 emoji 切成半个。

分页读会被标记（`m0591:148125`）：

```js
xe.set(r, {
  content: fn, timestamp: ..., offset: y, limit: so,
  ...Tn !== void 0 && { isPartialView: !0 }   // ← 截断时置位
});
```

## 3. ★ 第二个问题：为什么不会被读前置卡住

这是最关键的一节。Write 的门禁在 `m0591:73831`：

```js
if (!Fe || Fe.isPartialView) {
  ...
  let pt = !Fe && !Don(G) && !CFn(Xe, s.remoteCall) && xCe(Yt, G, s, s.permissions());
  ...
  if (!pt) return { result: !1, message: d_t, errorCode: 2 };
  ...
  return { result: !0 };      // ← 放行
}
```

注意 `pt` 的第一个条件：**`!Fe`** —— 只有「完全没读过」才是真。

于是三态语义是：

| 状态 | `Fe` | `pt` | 结果 |
| --- | --- | --- | --- |
| 从未读过 | `undefined` | 可能为真 → 进入严格判定 | 拒绝（`d_t` = "File has not been read yet"） |
| **读过但只是片段** | 存在，`isPartialView=true` | **`!Fe` 为假 ⇒ `pt` 为假** | **放行** ✅ |
| 读过且完整 | 存在，无 `isPartialView` | 不进入这个 if | 走 mtime 比对 |

**即：片段读 = 放行。CC 不要求读全。**

`isPartialView` 进入这个 `if` 只是为了走 `pt` 的豁免计算（模型分组
`CFn(Xe, ...)` 决定是否跳过门禁），不是为了拒绝片段读。

另外，Edit 的同类门禁（`m0591:212817`）结构与 Write **完全一致** ——
同样是 `!Fe || Fe.isPartialView` 进入，同样靠 `pt` 的 `!Fe` 起手放行片段读。

## 4. 另一个机制：`holdsOnlyStartOf`

`m0291_0x1177cdf0.js:86`：

```js
holdsOnlyStartOf(e) {
  let t = a(e);
  return this.startOnly.has(t) && !Oue(this.cache.get(t));
}
```

`startOnly` 是一组「只被读过开头」的路径。Write/Edit 里也有对应判断
（`m0591:73825` / `:73954` / `:153720`），用于**内部重读**的优化
（知道内容只剩开头，所以需要重新拉全文），**不是给用户的拒绝理由**。

## 5. 对照：Hlaudz 旧实现错在哪

```python
def check(self, path):
    ...
    if not rec.complete:
        return False, f"{p.name} 只读了片段。请 file_read 读完整文件后再写。"
```

`complete` 的算法（`builtin_tools.py:184` 旧代码）：

```python
registry.record(target, complete=(start == 1 and not keyword and end >= total))
```

要求**一次调用读到文件末尾**。40 KB 报告 ÷ 200 行默认 =
永远 `end < total` ⇒ `complete` 恒为 `False` ⇒ 覆盖写**恒被拒**。

三处与 CC 不同：

| | CC | Hlaudz 旧 |
| --- | --- | --- |
| 片段读后能覆盖写吗 | ✅ 能 | ❌ 不能 |
| 默认读行数 | 2000 | 200 |
| 超限时告知翻页方法 | ✅ 有 | ❌ 无（只说"去读完整"） |

**所以「删除门禁」是对的，但当时的理由只说对了一半。**
上一轮我写的是「提示词推翻了 Edit 的读前置」——
那只是表层。更根本的是：**我们实现了一个 CC 根本不存在的语义**
（片段读 ⇒ 拒绝覆盖），而且用必然失败的判据去实现它。

## 7. 这一轮的失误

| 失误 | 后果 | 怎么防 |
| --- | --- | --- |
| 手数行号两处 | `isPartialView: !0` 记成 148121（实际 **148125**）、`pt = !Fe && ...` 记成 73837（实际 **73834**） | 期望值先让脚本打印、确认后再填进断言；不要手数 |
| must_not 第一版写成「整模块不含」 | 真实的语义是「指定行不含」。`File has not been read yet` 在 notebook 分支里**确实存在**，用整模块否定会误判 | 否定断言必须限定作用域（行/函数），不是整文件 |
| 反向确认的注入串缩进不对 | `_inject_and_run` 报「找不到注入片段」，看起来像用例失败 | 注入串要从文件里**复制**，不要凭记忆写 |

## 8. 对 Hlaudz 的后续建议（未做）

1. **把 `DEFAULT_READ_LINES` 从 200 提到 2000**（对齐 CC）。现在门禁已删，
   200 不再是硬阻塞，但读大文件仍会多花好几轮翻页。
2. **截断横幅补上「怎么翻页」**（`Call file_read with start=N+1`）。
   当前 Hlaudz 的 header 只写「共 M 行，显示 X-Y」，模型得自己推下一步。
3. 若将来想恢复「冲突探测」，**不要**恢复 `complete` 判定；
   按 CC 的语义做：只比 mtime，变了就提示「你上次读之后文件被改过」，
   仍然放行（让模型自己决定要不要重读）。
