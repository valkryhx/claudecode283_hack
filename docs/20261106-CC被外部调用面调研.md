# Claude Code 被外部调用面调研（2.1.303 / 2.1.283）

> 目的：回答“别的 agent / 应用怎么直接调用 Claude Code”，并把可复刻的协议面拆到能实施的程度，
> 供 GenericAgent（GA）复刻。ACP 的完整协议细节见既有文档
> `docs/20261019-CC-ACP支持调研.md`，本文不重复，只做 303 复核与“调用面全景”。

---

## 0. 结论速览

1. **CC 二进制里没有 ACP。** 283 与 303 均 0 命中 `agent-client-protocol`、
   `session/update`、`session/new`、`fs/read_text_file`、`terminal/create`、
   `zed-industries`、`agentCapabilities`。
2. **ACP 是外部 adapter 造的。** Zed 侧的 `claude-code-acp` / `claude-agent-acp`
   订阅 CC 原生的 stream-json SDK 协议，再翻译成 ACP JSON-RPC。CC 本身仍然只会说自己的协议。
3. **CC 原生提供 8 条“被调用”通道**（按对 GA 的性价比排序）：
   - A. headless 单发：`claude -p` + `--output-format text|json|stream-json`
   - B. **双向 SDK streaming（主力）**：`--input-format stream-json --output-format stream-json --verbose`
   - C. 远程 I/O：`--sdk-url <ws-url>`，同一协议换传输
   - D. 后台会话：`--bg` + `claude attach/logs/stop/rm`
   - E. 预热池：`--await-claim` / `claim_session`
   - F. MCP 反向暴露：`claude mcp serve`
   - G. 内置 Agent SDK：`query()`（仍是 spawn CLI）
   - H. 钩子与权限代答：hooks、`hook_callback`、`--permission-prompt-tool`、`--permission-prompts`
4. **对 GA 的结论不变但更强**：先实现 B 的协议层（NDJSON + control protocol），
   ACP 只作为一层可选外壳。B 打通后，编辑器、其他 agent、Web 前端都能接；
   ACP 只是其中一种客户端话术。

## 4. 方式 A：headless 单发（`-p` / `--print`）

### 4.1 入口与参数

`m0775_0xf6ccb47.js @ 27`：

```text
--output-format <format>   "text"(default) | "json"(single result) | "stream-json"(realtime streaming)
--input-format  <format>   "text"(default) | "stream-json"(realtime streaming input)
```

补充约束 [S]：

- `--output-format=stream-json` 在 `--print` 下**必须同时给 `--verbose`**；
  否则报 `Error: When using --print, --output-format=stream-json requires --verbose`
  （`m1809_0x106dad73.js @ 24083`）。
- 是否进入非交互路径，由 `-p`、`--print`、`--init-only`、`--sdk-url`
  或 stdout 非 TTY 共同判定（`m0087_0xe5a8791.js @ 102-107`）。
- 存在一条“直接打开会话”的快速路径：stdin/stdout 是 TTY、输出为 text、
  且没有 `sdkUrl/jsonSchema/includePartialMessages/replayUserMessages/maxTurns/...` 时，
  直接走 `{open, prompt}`，不进入 headless 管线（`m0539_0xf3851b0.js @ 31`）。

### 4.2 单发输出

`json` / `stream-json` 的最后一帧是 `type:"result"`。字段以 303 的 zod schema 为准
（`m0120_0xe64eaf1.js @ 8077-8210`）：

```text
type: "result"
subtype: "success" | "error_during_execution" | "error_max_turns"
       | "error_max_budget_usd" | "error_max_structured_output_retries"
duration_ms, duration_api_ms, is_error, num_turns
result            // 最终文本
stop_reason, terminal_reason
total_cost_usd, usage, modelUsage
permission_denials, queued_turn_count, subagent_stats, safety_stops
structured_output // --json-schema 时
uuid, session_id
```

### 4.3 适用与限制

- 适合“问一次、拿结果”的 CI/脚本场景。
- 不适合需要中途批准、切模型、打断、追加输入的宿主——那些必须进方式 B。
- 单发也能“代答权限”，但只有两种粗粒度手段：
  `--permission-mode`、`--permission-prompt-tool`（见 §11）。

## 5. 方式 B：双向 SDK streaming（复刻主力）

### 5.1 启动命令

```bash
claude --print \
  --input-format stream-json \
  --output-format stream-json \
  --verbose \
  [--include-partial-messages] \
  [--replay-user-messages] \
  [--include-hook-events] \
  [--permission-prompts host|none] \
  [--session-id <uuid>] [--resume <id>] [--fork-session]
```

这条组合是 CC 自己和外部宿主（IDE、Agent SDK、云端 runner、desktop app）实际使用的形态，
在 303 里能看到多处内部 spawn 作为旁证：

- bridge 子进程（`m1392_0xfd18e89.js @ 297`）：
  `--print --sdk-url ... --session-id ... --input-format stream-json --output-format stream-json --replay-user-messages --resume=<sdkUrl>`
- self-hosted runner 子进程（`m0478_0xf1f25a4.js @ 4855`）：
  `--print --sdk-url ... --input-format stream-json --output-format stream-json --replay-user-messages --resume=<url> --debug-file ...`

### 5.2 成帧：NDJSON

- stdin / stdout 都是**一行一个 JSON 对象**，不打包成数组、不加长度前缀。
- 读取与分发集中在 `structuredIO`（`m1791_0x1069ac13.js`），
  写出用 `writeActivityLine(JSON.stringify(frame) + "\n")`（同文件 `@ 1131`）。
- 宿主必须按行缓冲、按行解析；任何一行损坏只影响该帧。

### 5.3 输入帧类型（宿主 → CLI）

`m1791 @ 938-948` 明确列了可接受的入站类型：

```text
user | assistant | system | control_request | control_response
control_cancel_request | bash_command | queued_notification
session_notice | workflow_launch
```

其中 `assistant` / `system` 主要用于恢复与回放；正常驱动只需要 `user` 与 `control_*`。

### 5.4 用户消息帧

SDK 侧构造（`m1407_0xfd5b0eb.js @ 3030-3044`，即 `ns()`）：

```json
{"type":"user",
 "session_id":"",
 "message":{"role":"user","content":[{"type":"text","text":"..."}]},
 "parent_tool_use_id":null}
```

发起方可以在首帧带 `client_composed: true` 表示内容由客户端拼装。
`parent_tool_use_id` 用于把消息挂到某个子代理的 tool_use 下。

### 5.5 输出帧（CLI → 宿主）

主要类型：`system` / `assistant` / `user` / `result`；开 `--include-partial-messages`
后额外有 `stream_event`（模型增量），开 `--include-hook-events` 后额外有 hook 生命周期帧。

**system/init** 是握手帧，字段定义在 `m0647_0xf520a62.js @ 232-270` [S]：

```text
type: "system", subtype: "init"
cwd, session_id
tools[]                     // 当前可用工具名
mcp_servers[{name,status,source?}]
model, permissionMode
slash_commands[]            // 可被用户调用的命令
terminal_slash_commands[]   // 与终端 UX 绑定的子集
apiKeySource, betas, claude_code_version
output_style
agents[]                    // 已加载 agent 类型
skills[], plugins[]
plugin_errors[]
```

宿主应以这一帧作为“会话就绪”的信号：拿到 `session_id`、工具清单、模型与权限模式后，
再开始发用户消息。

**assistant / user / result** 是对话帧；`result` 标记一个 turn 结束（字段见 §4.2）。
所有消息都带 `uuid`，`result` 还带 `session_id`，可用于把结果绑定回发起方（303 还增加了
`user_message_uuid` / `user_message_uuids` 用于精确关联，见 `m0120 @ 8189-8210`）。

**system 子类型**很长（`m0120 @ 8373-9231`），常见的包括：

```text
compact_boundary | status | api_retry | hook_started | hook_progress | hook_response
files_persisted | task_notification | task_started | task_updated
background_tasks_changed | session_state_changed | session_title_changed
permission_denied | permission_check_status | commands_changed | notification
ui_invalidate | ui_toast | ui_status | thinking_tokens | model_fallback
turn_handoff_available | worker_shutting_down
```

宿主应遵循 schema 自带的契约：**不认识的类型/子类型必须忽略**，
因为该集合会随版本增长（`m0120 @ 8348` 的说明原文如此）。

### 5.6 控制协议：信封与子类型

控制消息与对话帧共用同一条 NDJSON 流，靠 `type` 区分：

```json
{"type":"control_request","request_id":"<id>","request":{"subtype":"can_use_tool", ...}}
{"type":"control_response","response":{"subtype":"success","request_id":"<id>","response":{...}}}
{"type":"control_response","response":{"subtype":"error","request_id":"<id>","error":"..."}}
{"type":"control_cancel_request","request_id":"<id>"}
```

303 的合法子类型白名单在 `m1791_0x1069ac13.js @ 218`，**92 项**（脚本计数）[S]。按用途分组：

| 组 | 子类型（节选） |
| --- | --- |
| turn 控制 | `interrupt`、`cancel_async_message`、`stop_task`、`background_tasks`、`get_task_output` |
| 权限/对话 | `can_use_tool`、`request_user_dialog`、`elicitation`、`set_permission_mode`、`list_permission_rules`、`permission_*` |
| 模型/会话 | `initialize`、`set_model`、`set_max_thinking_tokens`、`rename_session`、`set_color`、`get_context_usage`、`get_session_cost`、`get_usage`、`export_conversation`、`get_plan` |
| MCP | `mcp_message`、`mcp_set_servers`、`mcp_reconnect`、`mcp_toggle`、`mcp_status`、`mcp_call`、`mcp_read_resource` |
| 环境/文件 | `set_cwd`、`register_repo_root`、`rewind_files`、`read_file`、`list_directory`、`get_workspace_diff`、`seed_read_state`、`file_suggestions` |
| 扩展/热重载 | `reload_plugins`、`reload_skills`、`reload_output_styles`、`update_settings`、`get_settings`、`get_hooks_listing`、`register_device_hooks` |
| 远程工具 | `remote_tools_announce`、`remote_tool_call`、`remote_plumbing_call`、`remote_tools_probe`、`remote_tools_reannounce` |
| UI surface | `ui_attach`、`ui_detach`、`ui_render`、`ui_press`、`ui_input`、`ui_select`、`ui_panes`、`ui_scroll`、`ui_focus`、`ui_prompt_edit`、`ui_prompt_read`、`ui_read_selection`、`ui_client_module` |
| 宿主生命周期 | `initialize`、`claim_session`、`turn_handoff`、`remote_control_work_secret`、`submit_feedback` |

**复刻时不要照抄全表。** 对 GA 来说必需的是：`initialize`、`interrupt`、`can_use_tool`、
`set_permission_mode`、`mcp_message`、`hook_callback`、`rewind_files`、`get_context_usage`。
其余（尤其 `ui_*`、`remote_*`、`claim_session`）属于宿主产品化能力，见 §12 的分期。

### 5.7 `initialize`：真正的会话握手

`initialize` 不是“打个招呼”，它把宿主的启动期配置一次性交给 CLI。
schema 在 `m0120 @ 9358-9405`，SDK 侧构造在 `m1407 @ 1590-1625`：

```text
subtype: "initialize"
hooks                        // 宿主实现的 hooks（回调 id 映射）
sdkMcpServers[]              // 宿主在进程内托管的 MCP server 名
sdkMcpServerConfigs{}        // 每个 server 的配置
sdkMcpServerManifests{}      // initialize / tools/list 结果（避免 CLI 再连一次）
jsonSchema                   // 结构化输出 schema
systemPrompt / appendSystemPrompt / planModeInstructions
systemPromptSnapshot / appendSubagentSystemPrompt
toolAliases
agents                       // 宿主定义的 agent 类型
title
skills[] / plugins[] / workspaceTrust
promptSuggestions / agentProgressSummaries / forwardSubagentText
supportedDialogKinds / forwardNestedSubagentToolCalls / rapidFollowupPreempt
attachServeRequest { workId, environmentId }
```

要点：

- 宿主可以在 `initialize` 里注册**进程内 MCP server**，CLI 不启动子进程，
  而是通过 `mcp_message` 控制帧与宿主交换 MCP JSON-RPC（见 §5.11）。
- `agents` 让宿主把自定义子代理类型注入会话，而不是写 `.claude/agents` 文件。
- `--await-initialize` 让 CLI 在启动时就先读这一帧，使 `plugins` 等启动期字段
  与命令行参数等价生效（`m0775 @ 27`）；宿主应在 spawn 后**第一行**就写 `initialize`。

### 5.8 `can_use_tool`：权限桥

方向是 **CLI → 宿主**，请求宿主批准一次工具调用。请求体构造在
`m1635_0x101da730.js @ 77263-77283`：

```json
{"type":"control_request","request_id":"<id>","request":{
  "subtype":"can_use_tool",
  "tool_name":"Bash",
  "display_name":"...",
  "input":{...},
  "tool_use_id":"...",
  "description":"...",
  "permission_suggestions":[...],
  "blocked_path":"...",
  "requires_user_interaction":true,
  "tool_kind":"..."
}}
```

schema 还包含（`m0120 @ 9466-9500`）：
`mcp_server`、`decision_reason*`、`matched_ask_rule`、`classifier_approvable`、
`default_to_no`、`agent_id`、`plugin`、`server_policy_ask_only` 等。

宿主回包：

```json
{"type":"control_response","response":{
  "subtype":"success","request_id":"<id>",
  "response":{"behavior":"allow"|"deny","updatedInput":{...},"message":"..."}}}
```

`behavior=deny` 且带 `message` 时，拒绝原因会进入模型上下文；
错误形态（`subtype:"error"`）不会冒充人工拒绝（`m1791 @ 767-794`）。

### 5.9 `interrupt` 与取消

`m0120 @ 9451`：

```text
subtype: "interrupt"
reason?, cancel_queued?, send_now?, message_uuid?
for_user_message_uuids?[], worker_epoch?
```

- `cancel_queued`：连同排队中的消息一起取消；
- `send_now`：把已排队消息立即插入；
- 响应（`m0120 @ 9462` 附近）会回报 `still_queued[]`、`send_now`、
  `turn: stopped|idle|spared`、`cancelled[]`。
- 单条排队消息用 `cancel_async_message`（`m0120 @ 9926`）。
- CLI 侧也有反向取消：`control_cancel_request` 通知宿主“这个请求不用回了”。

### 5.11 会话生命周期：id、恢复、分叉、回滚

CC 把“会话”落到本地 transcript（JSONL），对外用这些参数控制 [S]：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 指定会话 id | `--session-id <uuid>` | 宿主自己生成 UUID，便于幂等 |
| 继续最近会话 | `-c` / `--continue` | 当前目录最近一条 |
| 恢复指定会话 | `--resume <id>` | 恢复后重新进入同一 session |
| 分叉 | `--fork-session` | 复制历史到新会话，不动原会话 |
| 截断恢复 | `--resume-session-at <message-id>` | 只恢复到链上某条消息 |
| 恢复后立即查询 | `--reply-on-resume` | transcript 以 user 消息结尾时继续跑 |
| 回滚文件 | `--rewind-files <user-message-id>` | 恢复文件状态后退出（也可走控制帧） |
| 不落盘 | `--no-session-persistence` | 无持久化会话 |

坐标：`m0775 @ 27-28`、`m0087 @ 135`（`--fork-session`、`--no-session-persistence`）。

对宿主的含义：

- **恢复 = 重新 spawn CLI + `--resume`**，不是在一个长连接上“加载会话”。
  连接断了就重连，状态在 transcript 里。
- 宿主应把 `session_id` 当主键持久化；`result.user_message_uuid` 用于把回复
  绑定到具体一次发送（303 新增 `user_message_uuids` 支持一批发送合并成一个 turn）。

### 5.12 子代理

- 子代理消息通过 `parent_tool_use_id` 挂在父 `Task` 调用下。
- `--forward-subagent-text` / `initialize.forwardSubagentText` 决定是否把子代理文本
  透传到主流；`forwardNestedSubagentToolCalls` 决定嵌套子代理的工具调用是否上报。
- 宿主自定义 agent 类型走 `initialize.agents` 或 `--agents <json>`。
- 旁证：`m0757 @ 2631`、`m0120 @ 9376`。

### 5.13 宿主托管 MCP server（重要）

这是“让别的应用把自己的能力接进 CC”的关键机制：

1. 宿主在 `initialize.sdkMcpServers` 里声明 server 名；
2. CLI 需要 MCP 消息时发 `control_request{subtype:"mcp_message", server_name, message}`；
3. 宿主用 `control_response{response:{mcp_response: <JSON-RPC 响应>}}` 回；
4. 运行期可以用 `mcp_set_servers` 增删 server，`mcp_reconnect` / `mcp_toggle` 管理连接。

坐标：`m1407 @ 1393`（收到 `mcp_message` 并回 `mcp_response`）、
`m1407 @ 2411-2440`（`sendMcpServerMessageToCli`）、`m0120 @ 10217-10235`。
`initialize.sdkMcpServerManifests` 允许宿主提前给出 `initialize` / `tools/list` 结果，
省掉一次往返（`m1407 @ 1618-1700`）。

### 5.14 宿主实现 hooks

- `hook_callback`：CLI 把一次 hook 执行转给宿主，`callback_id` 对应
  `initialize.hooks` 里注册的函数（`m0120 @ 10028`；`m1407 @ 1387`）。
- `--include-hook-events`：把 hook 生命周期（`hook_started` / `hook_progress` /
  `hook_response`）也写进输出流，便于宿主做 UI 与审计（`m0775 @ 27`）。
- 这两者让“策略/审计/UI”不必写外部脚本，直接在宿主进程里实现。

## 6. 方式 C：`--sdk-url` 远程 I/O

帮助文本（`m0775 @ 28`）[S]：

```text
--sdk-url <url>   Use remote WebSocket endpoint for SDK I/O streaming
                  (only with -p and stream-json format)
```

不是另一套协议，而是把方式 B 的 stdin/stdout 换成网络端点：

- bridge 子进程启动时同时给 `--sdk-url` 与 `--resume=<sdkUrl>`
  （`m1392 @ 297`），说明 **URL 很可能本身就是会话端点**，恢复也走它 [A]。
- 内部把这种连接叫 `remote-io`（`m1794_0x106adc20.js`）：
  - 服务端写入的帧只能从 SSE 进，从 stdin 进会被丢弃并记日志（`@ 2896-2903`）；
  - 只有 `bridge` / `byoc` 宿主的 stdin 才是输入通道，其他情况下 stdin 数据被忽略（`@ 3440`）；
  - 有 `keep_alive` 帧与认证头重读逻辑（`@ 2046-2056`、`@ 3415`）。
- 权限默认目标也随之改变：有 streaming input 或 `sdkUrl` 时，
  未显式指定就按 `host` 处理（`m0017 @ 5873`）。
- 传输通道在内部被标记为 `lane: "sdk_url"` 或 `"print"`（`m1767 @ 196`）。

**对 GA 的启示**：协议层与传输层要解耦。先做 NDJSON over stdio，再抽一个
`Transport` 接口（stdio / WebSocket / HTTP+SSE），`--sdk-url` 那套就自然成立。

## 7. 方式 D/E：后台会话与预热池

### 7.1 后台会话

`--bg` / `--background`（`m0775 @ 28`）[S]：

> 启动后台会话并立即返回，打印一个 id；该 id 供 `claude attach`、`logs`、`stop`、`rm`
> 使用；`claude agents` 列出它们。配合 `--resume <id>` 可在后台继续同一会话。

子命令集合在 `m0087 @ 133`：`attach | logs | stop | kill | respawn | rm`。

还有一个隐藏入口 `--attach-serve <session_id>`：把“只做服务”的 helper 挂到一个
已绑定的云端会话上（`m0775 @ 28`），约束是必须非交互 + stream-json 输入输出
（`m0757 @ 3270`、`@ 3412`）。

### 7.2 预热池（低首字延迟）

`--await-claim`（`m0775 @ 27`）[S]：

> 作为 SDK 宿主的“预热备用进程”启动：在中立目录里带宿主机级选项启动，
> 跳过会话级启动工作，等待一个 `claim_session` 控制请求把进程绑定到它的会话。
> SDK 内部使用；要求 `--print` 且 stream-json 双向。

`claim_session` 的字段（`m0120 @ 10299`）：`cwd`、`env`、`additional_directories`、
`permission_mode`、`system_prompt`、`agents`、`title`、`sdk_mcp_servers`、
`include_initialize`、`workspace_trust` 等。CLI 侧处理在 `m0757 @ 2293`，
SDK 侧发送在 `m1407 @ 1892`。

这是“把进程启动成本前置”的工程手段，不是协议必需项；GA 若做常驻宿主服务可以后置。

## 8. 方式 F：`claude mcp serve`

实现入口：`m2059_0x10b4894d.js @ 1549` 导出
`gs as mcpServeHandler`。

关键事实 [S]：

- 默认 `stdio` 传输；可切 `--transport http`，需要 `--port`
  （`m2059 @ 1004-1007`）。
- `--transport http` 必须紧跟在 `"claude mcp serve"` 之后写，后续只允许
  `--port`、`--result-format`、`--session-tunnel`、`--debug`、`--verbose`（同处）。
- HTTP 模式下 hooks 不运行：`claude mcp serve --transport http never runs them`
  （`m0384 @ 419`、`m0459 @ 99522`）。
- 它暴露的是 CC 的**工具能力**，不是“对话会话”。303 的 changelog 里就有一条
  “`claude mcp serve` background Bash results …”（`m0713 @ 170`），
  说明 Bash 是其中一个工具 [A]。

适用边界：

- 适用：另一个 agent 只想要 CC 的稳健文件/命令工具实现，自己管对话与模型。
- 不适用：需要 CC 的 agent loop、上下文管理、权限语义、子代理、workflow。
  那些必须走方式 B。

## 9. 方式 G：内置 Agent SDK（`query()`）

## 10. 方式 H：权限代答与钩子

### 10.1 谁回答权限

`--print` 下有两个互斥的“权限宿主”目标（`m0775 @ 27`）[S]：

```text
--permission-prompts host|none
  host = SDK 宿主或 --permission-prompt-tool 回答
  none = 没有人回答：本该弹窗的一律自动拒绝（权限模式仍然决定其余行为）
```

默认是 `host`。选择规则在 `m0017 @ 5873`：有 streaming input 或 `sdkUrl` 时归 `host`。

### 10.2 MCP 工具代答

```text
--permission-prompt-tool <tool>   MCP tool to use for permission prompts (only works with --print)
```

限制：

- 需要用户交互的 MCP 工具不能走这条通道，错误文本是
  `MCP tool requires user interaction; not supported via --permission-prompt-tool`
  （`m0043 @ 386`）。
- 只支持 stdio 传输的 MCP server；
  否则报 `--permission-prompt-tool (permission prompts reach the host over stdio; an MCP tool cannot answer them here)`
  （`m0757 @ 2640`）。
- 走这条路的拒绝会被记为 `permission-rule` 且没有 `user_feedback`，
  因为该 wire 不携带“人工来源”信号（`m0120 @ 7802` 的字段说明）。

### 10.3 结论

`--permission-prompt-tool` 是“旧式、粗粒度”的代答；
**方式 B 的 `can_use_tool` 才是完整形态**（能传 `tool_use_id`、suggestions、
blocked_path、是否需用户交互等）。GA 复刻应直接做 `can_use_tool`，不要绕 MCP 工具。

## 11. 与 ACP 的逐项映射

ACP 的完整拆解见 `docs/20261019-CC-ACP支持调研.md` §3-§5。这里只给“如果 GA 要同时支持
ACP 客户端”时的映射表：

| ACP 方法/事件 | CC 原生对应 | 说明 |
| --- | --- | --- |
| `initialize` | 启动 CLI + `initialize` control request | 能力协商在两边各有一层 |
| `session/new` | `--session-id <uuid>` + `system/init` | CC 的会话由进程创建 |
| `session/prompt` | `{"type":"user",...}` 帧 | turn 开始 |
| `session/update`（文本增量） | `stream_event`（需 `--include-partial-messages`） | 增量粒度不同，需要聚合 |
| `session/update`（工具调用） | `assistant.message.content[].tool_use` | 结构化程度更高 |
| `session/update`（计划/状态） | `system{subtype:status/task_*}` | 需筛选映射 |
| `session/request_permission` | `can_use_tool` control request | 字段可一一对应 |
| `session/cancel` | `interrupt` control request | `cancel_queued` 控制范围 |
| `session/load` | 重新 spawn + `--resume <id>` | 不是长连接上的 load |
| `session/close` | 关闭 stdin / 终止进程 | — |
| 客户端能力（fs/terminal） | CC 自带工具，不经客户端 | 这是 ACP 与 CC 的最大结构性差异 |

**结构性差异**：ACP 假定“文件系统/终端由客户端提供”，CC 假定“工具在 agent 进程内”。
所以 CC 的 ACP adapter 必须把 ACP 的 `fs/*`、`terminal/*` 能力**降级/忽略**，
把工具执行留在 CC 侧；反过来，ACP 客户端看到的是 CC 的工具，而不是自己的。
复刻时不要试图把 GA 的工具搬到客户端去执行，除非你明确要 ACP 的沙箱模型。

## 12. 给 GenericAgent 的复刻方案

### 12.1 目标分层

```text
外部客户端（编辑器 / 其他 agent / Web / CLI / ACP client）
        │  目标话术：NDJSON（首选）或 ACP JSON-RPC（可选外壳）
        ▼
协议层  codec + session registry + control dispatcher
        │  GA 内部事件
        ▼
GA 现有 agent loop（工具、权限、workflow、subagent、transcript）
```

原则：

1. **不要改 GA 主循环去说某种客户端协议。** 协议层只订阅/注入事件。
2. **先 NDJSON，后 ACP。** NDJSON 是 CC 的原生形态，事件最全；ACP 只映射子集。
3. **传输与协议解耦。** stdio 先行，再 WebSocket/HTTP。
4. **会话状态落在 transcript 上**，连接断开不等于会话结束。

本次在 GA 仓 `genericagent/` 与 `docs/` 做关键词检索，未见 stream-json / ACP
协议实现；具体接入点（事件总线、turn 生命周期、权限请求）需按 GA 代码核对后落地。

### 12.2 P0：最小可用闭环（建议 1-2 周）

必须打通的 12 条：

1. 启动参数：`serve --input-format stream-json --output-format stream-json [--verbose]`
2. NDJSON 读写：一行一帧，坏行不影响后续
3. `initialize` 接收：systemPrompt、agents、mcp servers、hooks（可先只收不用）
4. `system/init` 发送：session_id、tools、model、permissionMode、slash_commands
5. 用户消息接收：`type:"user"` → GA turn
6. assistant 文本/工具调用输出
7. `result` 输出：success/error、num_turns、usage、cost、session_id
8. `can_use_tool` 请求 + allow/deny 回包（含 updatedInput）
9. `interrupt`（至少 `cancel_queued`）与 `control_cancel_request`
10. 错误路径：启动失败、模型错误、工具异常都要有结构化 result
11. 进程退出：stdin EOF = 优雅结束；异常退出要有可诊断 stderr
12. E2E：一个最小宿主脚本跑通“提问 → 工具 → 批准 → 结果”

验收标准：宿主只依赖公开帧就能完成一次带权限确认的编码任务，
且中途打断后能收到 `result` 而不是挂死。

### 12.3 P1：产品化（2-4 周）

- `--session-id` / `--resume` / `--fork-session` 与 transcript 对齐
- `set_permission_mode` / `set_model` / `set_max_thinking_tokens`
- 宿主托管 MCP：`initialize.sdkMcpServers` + `mcp_message` + `mcp_set_servers`
- 宿主 hooks：`hook_callback` + `--include-hook-events`
- 子代理：`parent_tool_use_id`、`forwardSubagentText`、`agents`
- 增量输出：`stream_event`（对应 `--include-partial-messages`）
- 上下文与成本：`get_context_usage`、`get_session_cost`、`get_usage`
- 回滚：`rewind_files`（先做 dry_run）

### 12.4 P2：按需

- 远程传输（WebSocket / HTTP+SSE）
- 预热池（`claim_session`）
- UI surface（`ui_*`）——只有做远程 UI 才需要
- `remote_tools_*`——只有做“宿主提供工具给 agent”才需要
- ACP adapter

### 12.5 明确不要照抄

| 项 | 原因 |
| --- | --- |
| 92 项 control 子类型全量 | 大量是 Anthropic 产品面（cloud、chrome、feedback、oauth） |
| `ui_render` 组件协议 | 与 CC 的 Ink 组件模型强绑定，GA 前端不同 |
| `--cloud` / bridge / teleport | 绑定 Anthropic 云端，不可复刻也不必要 |
| `--permission-prompt-tool` 旧通道 | 能力弱于 `can_use_tool`，会制造两套权限语义 |
| 把工具搬到客户端执行（ACP fs/terminal） | 与 CC 的工具在环模型冲突 |

## 14. 风险与边界

1. **协议是私有的、会变。** 303 比 283 多了约 40 个控制子类型；
   schema 自己都写着“消费者应忽略不认识的类型”。复刻时要有版本容忍。
2. **`--verbose` 是硬要求。** 少了它 `stream-json` 直接报错，不是可选项。
3. **`--sdk-url` 的 stdin 语义因宿主类型而异**，不要假设“写了就一定被读”。
4. **权限拒绝没有统一的人机来源标记**，审计要自己在宿主侧记录。
5. **MCP 代答通道能力受限**（仅 stdio、不能处理需交互的工具）。
6. **ACP 的 fs/terminal 客户端能力与 CC 不兼容**，映射时只能降级。
7. **不要用模块号跨版本对齐**：283→303 模块编号、大小、共享 chunk 都变了，
   必须按本文字面量与导出名复核（见 AGENTS.md §9）。

## 17. 一句话回答

> **Claude Code 不支持 ACP；它支持一套私有的 stream-json SDK 协议。**
> 其他 agent / 应用要调用 CC，正确姿势是 spawn CLI，走
> `--print --input-format stream-json --output-format stream-json --verbose`，
> 用 `initialize` 握手、`user` 帧发消息、`can_use_tool` 管权限、`interrupt` 打断、
> `--resume` 恢复；ACP 只是外部 adapter 在这套协议上套的一层壳。
>
> 给 GA 的复刻顺序：**先协议层（NDJSON + 控制帧 + 权限/取消/恢复），
> 再传输层（stdio → WebSocket），最后才是 ACP adapter。**
