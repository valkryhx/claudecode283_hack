## 8. 映射方法与反例

### 8.1 快速定位流程

1. 在 283 文档中找旧模块和可搜索符号；
2. 在 303 的 `INDEX.tsv` 找大小/`wf_hits` 相近的模块；
3. 搜 283 的独有字符串或导出别名；
4. 看 303 模块末尾 `export { ... }`；
5. 用 `cross-version-candidates.json` 的候选做交叉检查；
6. 最终在文档里同时写“文件 + 行号 + 可搜索字符串”。

### 8.2 不能直接相信相似度的例子

| 例子 | 原因 |
| --- | --- |
| `m1322 → m1496` | 候选相似度高，但 `m1496` 的 `rerun_workflow_run` 是 GitHub 工具权限，不是 dynamic workflow |
| `m1657` | 相似度很低，但人工确认它是 rewind 的 re-export 桶 |
| `m1996 → m2173` | 相似度很低，但导出名精确证明它是 task API 友好名 re-export |
| `m1075 → m1241` | 相似度低，但 `name: "workflows"` 与命令行为可确认 |
| `m1372 → m2259` | 真正 launch state 在 `m2259`；`m1809` 只是调用点 |

结论：**候选分数用于排序，导出名和字符串用于定案。**

## 9. 303 新增/变化的入口

1. **hooks module**：`m0103` 的 `scripts/bundle-builtin-hooks-module.ts`、`hooks/register.ts`、`mods/` 虚拟路径。
2. **hooks module runtime**：`m0249` 处理匹配、重入、worker 替换、`.catch` 与 respawn。

4. **单隐式团队**：`team_name` 在 `m0621:347` 已废弃并忽略。

详细说明见 hooks 与 mods 两份专项文档。
