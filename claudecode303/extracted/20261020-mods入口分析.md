# Claude Code 2.1.303 mods 入口分析

> 日期：2026-10-20  
> 基准：`reconstructed303/deminified/` 当前行号；`m0459` 为共享大模块，符号仍为压缩名。  
> 目标：解释 303 的 `mods` 产品层是什么、从哪里加载、如何排序和隔离，给出可复刻入口。

## 0. 一句话结论

303 的 `mods` **不是独立的 `mods/` 目录 API**。它是产品层对以下三类的称呼：

1. 用户安装的 plugin；
2. plugin 提供的 function hooks / hooks module；
3. 内置安全 plugin（`cc-plugin-sec-default@builtin`）。

代码内部仍大量使用 `plugin`、`plugins`、`hooks module`、`builtinPlugins`。复刻时不要把 `mods` 当成与 plugin 平行的第二套插件系统。

### 1.1 一个容易误判的点

`m0103:239-240` 里的：


是 **builtin hooks module 的 import 虚拟路径前缀**，不是用户磁盘上的通用 `mods/` 插件目录。`m0103:245-247` 会把 `builtin-hooks-module:mods/...` 映射为 `mods/...`，再交给 bundle 逻辑解析。

### 4.1 取内置 hooks module

`m0459:106230`：


也就是说，**native hooks module 是 built-in 特权路径**；普通安装 plugin 的 module 在 plugin sandbox 中运行。

## 5. 来源与顺序

### 5.1 mod 来源

`m0459:106155`：

```js

```

遥测 `tengu_plugin_function_hooks_mod_load` 会带：

- `plugin_id_hash`；
- `tier`；
- `is_hosted`；
- `outcome`；
- `hook_patterns`（loaded 时）。

`m0459:106198-106213` 的 `tengu_plugin_function_hooks_mods_first_turn` 汇总：

- `loaded_mods`；
- `failed_mods`；
- `mod_dispatches`；
- 按 `provenance_installed` / `plugin_dir` / `dev_mods` / `managed` 分桶。

### 5.2 managed plugin 顺序

`m0062:8045-8046`：

- `prependPlugins`：managed plugin 的 hooks **最先、最外层**执行；
- `appendPlugins`：managed plugin 的 hooks 最后、最内层执行；
- 未列出的 managed plugin 排在列出的 managed plugin 之后；
- user/project/marketplace plugins 再之后；
- 最后是 builtin plugins。

`m0250:708-777` 的 `h3()` 解析：

- `prependPlugins` / `appendPlugins`；
- policySettings / userSettings 的来源；
- `outermost`；
- shadowed 状态；
- managed plugin 冲突。

`m0459:134692-134730` 处理 managed plugin 冲突；冲突时不会静默覆盖。

### 5.3 默认安全 plugin seat

`m0250:28-54`：

- `sec-default` 默认最外层；
- 有 managed settings 或 Team/Enterprise 组织时 seat 生效；
- 如果设置了 `prependPlugins`，由组织显式列出 `cc-plugin-sec-default@builtin`；
- seat 一旦成立，本会话持续到结束。

### 6.1 `allowManagedModsOnly`

`m1824:277`：

```text
mods are limited to your organization's by policy (allowManagedModsOnly);
${name} was not loaded
```

`m1824:302` 读取 `allowManagedModsOnly`；`m1824:421-427` 在 `plugin.register` hook 里拒绝不合规的 mod。

### 6.2 `allowModsToOverrideDenyRules`

`m1824:275`：

```text

```

默认语义是：用户安装的 mod 不能覆盖组织/设置里的 deny rules；只有策略显式允许时才可覆盖。

### 7.1 常量

`m1824_0x108080f9.js:236-237`：

其中 `MOD_FOLDER` 的导出别名指向 `b`，值为 `"sec-default"`；不要把它误读成通用的 `mods/` 根目录。

### 7.2 注册

`m1824:429-435`：


含义：

- 默认最外层；
- 在 managed settings 或 Team/Enterprise 组织下生效；
- 保护组织的 classic hooks、prompt、settings、tool policy；
- 自己不新增策略；
- 通过 `plugin.register` hook 对用户安装 plugin 做准入判断。

### 7.3 准入判断

`m1824:419-427`：


关键点：

- 读 managed settings；
- `xe()` 判断 `allowManagedModsOnly`（`m1824:301-304`）；
- 不合规时 `refuse`；
- 读取/判断异常时也 fail-closed 到 `refuse`；
- `plugin.register` 失败会记录到 debug，但不会静默放行。

### 7.4 deny rule 覆盖

`m1824:271-299`：

- 组织/设置里的 deny rule 默认压过用户安装 plugin；
- `allowModsToOverrideDenyRules` 只有在策略允许时才放宽；
- `G()` 的默认结果就是“不可覆盖”，不是“插件优先”。

## 8. 远程 rollout 与 worker

### 8.1 installed mods 的远程开关

`m0239_0xe909bc9.js:55`：

```text
Mods you installed aren't running in this session. Your organization's settings couldn't be read,
so it isn't known whether it allows them.
```

`m0239:60`：

```text
installed mods are off for now: the rollout switch for them reads off;
they load again when it reads on, and built-in mods keep running
```

这说明 rollout 失败时：

- 用户安装 mods 默认关闭；
- built-in mods 继续运行；
- 组织设置读取失败不能假设允许。

相关入口：

- `m0239:376` organization mods 加载失败；
- `m0239:437` 等待 organization mods；
- `m0459:130848-130854` worker mods off；
- `m0459:130319-130327` worker respawn 遥测；
- `m0881:100-101` hooks modules 关闭提示。

### 8.2 worker 边界

- builtin hooks module 可走 native link；
- 普通 plugin hooks module 在 plugin sandbox / hop 中运行；
- `m0249:1815-1853` 的 `run` / `hop` 同时支持两种路径；
- worker 被替换时，正在进行的 dispatch 由 `.catch` 接管（`m0249:1385-1440`）；
- worker 崩溃/respawn 入口在 `m0459:130929`、`:131167` 附近。

## 10. 复刻清单

### 必做

1. 把 mods 建模为 **plugin**，不要另起一套平行 API。
2. 支持 `enabledPlugins`、`prependPlugins`、`appendPlugins`。
3. managed settings 优先于 user/project/local；managed-only 模式必须 fail-closed。
4. 每个 plugin 有 manifest、hooks 配置、可选 hooks module。
5. builtin hooks module 用 scan/shipped 两种注册方式。
6. hooks module 与普通 plugin 分沙箱：native 只给 builtin，普通 plugin 走 sandbox/hop。
7. module dispatch 支持 event matcher、reentry 过滤、`leftOut`、pinned matcher。
8. worker 被替换/崩溃时支持 respawn 与 `.catch` 接管。
9. 默认安全 plugin 最外层；`allowManagedModsOnly` 与 deny rule 保护必须实现。
10. rollout 开关失败时关闭 installed mods，保留 built-in mods。

### 推荐

11. 遥测按 `installed` / `plugin_dir` / `dev_mods` / `managed` 分来源。
12. 记录 `loaded_mods`、`failed_mods`、`mod_dispatches` 和 `hook_patterns`。
13. managed plugin 冲突显式报错，不做 last-write-wins。
14. `next.to()` 只对 managed plugin 开放。
15. 在 server tenant 禁止 native hooks module。
16. 为 plugin authoring 提供命令提示和可读错误。
