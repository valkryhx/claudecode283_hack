## 3. 模块提取

### 3.1 阈值与结果

用户指定 303 使用 **6 MiB** 模块上限：

```bash
python tools/extract_bun_modules.py \
  "D:/git_repos/claude_hack/claudecode303/claude.exe" \
  "D:/git_repos/claude_hack/claudecode303/modules" \
  --max-size 6M
```

| 指标 | 结果 |
| --- | ---: |
| `// @bun @bytecode` marker | 2,433 |
| 有效模块 | 2,431 |
| 模块总大小 | 46,655,355 B |

| 最大模块 | `m0459_0xecff32a.js`，4,995,056 B |

`tools/extract_bun_modules.py` 同时支持 `--max-size 4M`；已用该阈值精确复现 283 的 2,135 个模块和 `INDEX.tsv`，说明 303 的模块切分不是特例脚本。

### 3.2 两个跳过区

| marker | 偏移 | 大小 | 判断 |
| ---: | ---: | ---: | --- |
| 1 | `0x658abf5` | 132,884,179 B | 超大非模块区，NUL 很早出现，尾部可打印率约 0.238 |
| 2432 | `0x110c3a31` | 4,214,383 B | 仅开头 2,813 B 像 JS，随后进入多模块/二进制区，可打印率约 0.448 |

跳过的是“不应被当成一个模块”的 span，不是删除源码。所有有效 marker 之间的原始字节均写入 `modules/`。

### 3.3 索引格式

`modules/INDEX.tsv` 字段：

```text
idx  off  size  wf_hits  file  tokens
```

示例：

```text
0    0x658abe3     18  0  m0000_0x658abe3.js
2    0xe4452c8   1356  0  m0002_0xe4452c8.js
2431 0x110c36e1   848  0  m2431_0x110c36e1.js
```

`wf_hits` 是大小写不敏感的 `workflow` 计数，只用于快速筛选，不等价于“该模块属于 workflow 子系统”。

### 5.1 超大模块

以下 3 个模块超过 1 MiB，按既有安全规则跳过 AST 改名并复用 `full/`：

- `m0459_0xecff32a.js`（4,995,056 B）
- `m1496_0xfe682a4.js`（1,546,315 B）
- `m1635_0x101da730.js`（1,768,541 B）

因此：

- 行号和字符串可直接检索；
- 但符号仍是压缩名，不能把 `m0459` 中的 `E6r`、`N0` 等说成已经完成可读化。

### 5.2 改名账本

`reconstructed303/deminify-names.json` 每条记录包含：

```json
{"file":"m0002_0xe4452c8.js","old":"n","new":"CLAUDE_CODE_SESSION_KIND","level":"B","why":"成员初始化 n = ?.CLAUDE_CODE_SESSION_KIND"}
```

证据级别含义沿用项目规范：

- **S**：代码中直接写死的字符串、属性名、schema 或导出别名；
- **A**：强语义推断，几乎无歧义；
- **B**：由调用点、初始化值或上下文推断；
- **C**：弱推断，仅供阅读，不应当作还原事实。

## 7. 检索方法

### 7.1 先找入口，不要先扫 6 MB 大模块

推荐顺序：

1. `claudecode303/modules/INDEX.tsv` 按 `wf_hits`、大小和 token 缩小范围；
2. `reconstructed303/deminified/` 搜字符串、属性名、导出别名；
3. 命中后看模块首尾的 `export { ... }`；
4. 大模块 `m0459` 直接搜字符串/属性名，再用行号定位。

示例：

```bash
cd /d/git_repos/claude_hack
grep -RIn --include='*.js' 'allowManagedHooksOnly' reconstructed303/deminified | head
grep -RIn --include='*.js' 'hooks/register.ts' reconstructed303/deminified | head
grep -RIn --include='*.js' 'installed_mods' reconstructed303/deminified | head
```

### 7.2 行号基准

文档中的 `mXXXX:NNNN` 默认指：

- `reconstructed303/deminified/mXXXX_*.js` 的当前行号；
- 大模块未 AST 改名时，行号仍有效，但符号名是压缩名。

重新格式化会改变行号，因此每个结论尽量同时给出文件名、行号和可搜索字符串。

## 9. 已知限制

1. **候选表不是等价证明**：`cross-version-candidates.json` 只做相似度排序，不能替代导出名/字符串核对。
2. **3 个大模块未去混淆**：`m0459`、`m1496`、`m1635` 保留压缩符号。
3. **4 个 beautifier 回退**：不影响字节完整性，但格式不美观。
4. **部分子系统只做入口分析**：本次重点为 hooks、mods、workflow、rewind、Agent Team 的入口和链路；没有声称每个 UI 细节都已逐行还原。
5. **证据等级必须保留**：文档中的“推断”不得在复刻时升级成“源码事实”。
