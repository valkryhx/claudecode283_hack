## 0. 一句话结论

303 的 hooks 是“**配置 schema + 输入协议 + 输出协议 + 执行器 + 来源合并 + 安全门禁 + async/worker**”组成的系统。用户可见配置支持 **5 种类型**，事件表为 **33 个**；真正执行核心在共享大模块 `m0459_0xecff32a.js`，配置和 schema 分别在 `m0062`、`m0120`、`m0353`。

### 2.1 关键事件语义

| 事件 | 触发点 / 用途 |
| --- | --- |
| `PreToolUse` | 工具执行前；可 allow/deny/ask/defer、改写 `updatedInput` |
| `PostToolUse` | 单个工具成功后；可追加上下文、改写工具输出 |
| `PostToolUseFailure` | 单个工具失败后；可追加上下文 |
| `PostToolBatch` | 一批并行工具全部结束后恰好一次；输入带完整 `tool_calls` |
| `PermissionRequest` | 权限询问阶段；可 allow/deny、更新权限 |
| `PermissionDenied` | 权限被拒绝后；可返回 `retry` |
| `UserPromptSubmit` | 用户 prompt 提交时；可注入上下文或阻断 |
| `UserPromptExpansion` | slash command / MCP prompt 展开时 |
| `SessionStart` / `SessionEnd` | 会话生命周期 |
| `Stop` / `StopFailure` | 主循环停止或停止失败 |
| `SubagentStart` / `SubagentStop` | 子 agent 生命周期 |
| `TeammateIdle` | teammate 空闲 |
| `TaskCreated` / `TaskCompleted` | 后台任务生命周期 |
| `CwdChanged` / `FileChanged` / `DirectoryAdded` | 工作目录与文件系统变化 |
| `MessageDisplay` | 只改写屏幕显示，不改变已存消息 |

## 3. 五种用户可见 hook 类型

`m0062_0xe4ee087.js:2636` 的 `dh()` 返回五个 schema：

| 类型 | 核心字段 | 说明 |
| --- | --- | --- |
| `command` | `command`、`args?`、`shell?`、`timeout?`、`onFailure?`、`async?`、`asyncRewake?` | 最常用；有 shell 形式和 exec 形式 |
| `prompt` | `prompt`、`model?`、`timeout?`、`continueOnBlock?` | 用小模型评估 hook 输入 |
| `mcp_tool` | `server`、`tool`、`input?`、`timeout?` | 调用已配置的 MCP 工具 |
| `http` | `url`、`headers?`、`allowedEnvVars?`、`timeout?`、`onFailure?` | POST hook 输入 JSON |
| `agent` | `prompt`、`model?`、`timeout?` | Agentic verifier，默认 60 秒、默认 Haiku |

### 3.1 command

```json
{
  "type": "command",
  "command": "node .claude/hooks/check.js",
  "args": ["--mode", "strict"],
  "shell": "bash",
  "timeout": 30,
  "onFailure": "continue",
  "statusMessage": "checking",
  "once": false,
  "async": false,
  "asyncRewake": false
}
```

要点：

- 有 `args` 时是 **exec form**：`command` 当可执行文件，`args` 逐元素替换占位符，不经过 shell（`m0062:2640`）。
- 无 `args` 时走 shell；Windows 上没有 Git Bash 时默认 PowerShell。
- `onFailure: "block"` 可把“无法启动、超时、非 0/2、输出无效”等失败提升为阻塞；但 `Stop`、`SubagentStop`、`TaskCompleted`、`TeammateIdle` 忽略该提升（`m0459:57412-57435`）。
- `async: true` 后台运行；`asyncRewake: true` 在 exit code 2 时唤醒模型。
- `cloud: "device" | "skip"` 控制 cloud 会话是否可在本机执行。

### 3.2 prompt / agent

- `prompt` 用 `$ARGUMENTS` 接收 hook 输入 JSON。
- `agent` 是带工具能力的 verifier；schema 描述写明默认 60 秒、默认 Haiku。
- 两者的 `continueOnBlock` 只影响 `decision:"block"` 的 continue 语义，不改变事件本身的硬门禁。

### 3.3 mcp_tool / http

- `mcp_tool` 的 `input` 支持 `${tool_input.file_path}` 一类路径插值。
- `http` 的 headers 可插值环境变量，但只有 `allowedEnvVars` 和全局 `httpHookAllowedEnvVars` 交集内的变量可用。
- HTTP hook 必须返回 JSON；空 body 当 `{}`，非 JSON 报错（与 command 的纯文本 stdout 不同）。

## 4. 配置结构

`m0062:2713`：

```js
{
  matcher: "Write|Edit",       // 可选
  hooks: [ /* Handler[] */ ]
}
```

外层：

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash", "hooks": [{ "type": "command", "command": "..." }] }
    ],
    "Stop": [
      { "hooks": [{ "type": "command", "command": "..." }] }
    ]
  }
}
```

- matcher 是字符串；常见形式是工具名、`Edit|Write`、空字符串匹配全部。
- `PreToolUse` / `PermissionRequest` 的配置错误采用 fail-closed：`m0062:2815` 的 `T4` 集合与 `m0062:2893` 的提示说明，坏 entry 可能正是权限守卫，不能静默放行。
- `hooks` 既可以是 matcher 数组，也可以由 hooks module 提供；`m0062:3675` 的报错写明 “hooks.json must have `hooks` ... or `modules` ... or both”。

`m0459:160149-160175` 的 `qo()`：

- 把输入序列化为 JSON；

## 6. 输出 schema（从 stdout 读回的 JSON）

### 6.1 顶层字段

`m0120:7180`：

```js
{
  continue?: boolean,
  suppressOutput?: boolean,
  stopReason?: string,
  decision?: "approve" | "block",
  systemMessage?: string,
  terminalSequence?: string,
```

`terminalSequence` 只允许通知/标题类 OSC（0、1、2、9、99、777）和 BEL，其它序列被丢弃（`m0120:7186`）。

| `UserPromptSubmit` | `additionalContext` | `m0120:7089` 附近 |

### 6.3 输出校验

`m0459:155506`：

```text
Hook JSON output validation failed —
```

关键规则：

- `hookSpecificOutput` 必须带正确的 `hookEventName`；缺失时报 `hookSpecificOutput is missing required field "hookEventName"`（`m0459:155549`）。
- `PermissionRequest.decision` 必须是 `{"behavior":"allow"}` 或 `{"behavior":"deny", ...}`（`m0459:155550`）。
- 顶层 `decision` 是旧式 `approve|block`；PreToolUse 的 `ask` 必须放进 `hookSpecificOutput.permissionDecision`（`m0459:155551`）。
- 未知字段会被报告；帮助文本在 `m0459:155560-155609`。
- 输出有未完成 JSON / stdio 提前关闭时，不会把可疑捕获当成有效 verdict（`m0459:51980-51988`）。

### 6.4 exit code 语义

303 执行器仍按 command hook 的核心语义处理：

| exit code | 语义 |
| --- | --- |
| `0` | 成功；stdout 可以是 JSON，也可以是普通文本 |
| `2` | 阻塞错误；stderr/JSON 反馈给模型，PreToolUse 上等同 deny |
| 其它非零 | 非阻塞错误；默认只给用户看，不拦截动作 |
| 超时/取消 | `hook_cancelled`，不计成功/失败 |
| spawn 失败 | `hook_error_during_execution` / 非阻塞错误 |

303 的新增点是 `onFailure`：对可阻塞类型，`onFailure:"block"` 会把超时、启动失败、无效输出等提升为阻塞；但 `Stop`、`SubagentStop`、`TaskCompleted`、`TeammateIdle` 明确忽略该提升（`m0459:57412-57435`）。

## 7. 执行链路

### 7.1 PreToolUse 专用入口

`m0459:109991`：

```js
async function* cur(e, n, r, s, h, y, S, w) { ... }
```

- `e`：工具名；
- `n`：`tool_use_id`；
- `r`：`tool_input`；
- `s`：tool use context；
- 在 `m0459:110001-110008` 构造 PreToolUse 输入；
- 在 `m0459:110010-110024` 通过 `ox()` 执行 hook 集。

### 7.2 通用执行器

| 入口 | 作用 |
| --- | --- |
| `m0459:159791` `ox(e)` | 旧式/单次执行包装，先做 function hook 与来源判断 |
| `m0459:159937` `E6r({...})` | **主执行 generator**：信任检查、收集、匹配、进度、并行执行、结果聚合 |
| `m0459:160120-160143` | 发 `hook_progress` 事件 |
| `m0459:160149-160175` | 输入 JSON 序列化与大小检查 |
| `m0459:160180` 起 | 并发执行各 handler，聚合 blocking/additionalContext/updatedOutput 等 |

### 7.3 执行顺序（概念上）

```text
事件发生
  ├─ PreToolUse：cur() 构造输入
  └─ 其它事件：E6r()/ox()
       ├─ workspace trust 检查
       ├─ 收集 session/plugin/builtin/function hooks
       ├─ matcher 过滤
       ├─ 生成 hook_progress
       ├─ 按类型执行 command/prompt/agent/http/mcp_tool/callback/function
       ├─ 解析 stdout / JSON / exit code
       ├─ 校验 hookSpecificOutput
       └─ 汇总 blockingError / additionalContext / updatedInput / updatedOutput / systemMessage
```

### 7.4 function / callback hook

- `callback` 在 `m0459:160269` 起处理；适合 SDK host 提供的回调。
- `function` 在 `m0459:160334` 起处理；只在 REPL/Stop 等上下文可用。
- 它们不是用户 settings 的 5 种类型之一；属于内置/SDK 通道。复刻时可以先把它们视为“进程内 handler”。

### 7.5 workspace trust 与 cloud

- `m0459:159965`：未接受 workspace trust 时直接跳过 hook，并打印 `Skipping ... hook execution - workspace trust not accepted`。
- `m0459:160010`：cloud 会话会跳过 `agent` / `prompt` hook；command/http 是否可执行由 `cloud` 字段和会话策略决定。
- `m0459:159923`：cloud/Cowork 等场景会丢弃 hook 的 `setMode` 权限更新，防止 hook 直接切换权限模式。

## 10. async 与 worker

### 10.1 async hook

- `async: true`：后台运行，不阻塞当前动作。
- `asyncRewake: true`：后台运行，但 exit code 2 时唤醒模型；`m0062:2648` 明确“Implies async”。
- `rewakeMessage` / `rewakeSummary`：控制唤醒时的模型前缀和用户摘要。
- async 注册表从 `m0459:58003` 起；`m0459:58014` 的默认 `asyncTimeout` 是 `15000` ms。
- `asyncRewake` 的 exit code 2 处理在 `m0459:157142`、`157190-157218`。

## 11. 复刻清单（最小可用）

### 必做

1. 定义 `hooks: Record<event, { matcher?, hooks: Handler[] }[]>`。
2. 先实现 5 个高频事件：`PreToolUse`、`PostToolUse`、`UserPromptSubmit`、`Stop`、`SessionStart`。
3. stdin 写公共字段 + `hook_event_name` + 事件专属字段。
4. stdout 支持 `continue`、`decision`、`reason`、`systemMessage`、`hookSpecificOutput`。
5. 先实现 PreToolUse 的 `permissionDecision`、`permissionDecisionReason`、`updatedInput`、`additionalContext`。
6. exit code：0 成功、2 阻塞、其它非零非阻塞。
7. 每个 handler 有 timeout 和 abort；输出/输入有大小上限。
8. matcher 支持 `*` / `.*`、`A|B`、正则。
9. 同一事件多个 handler 并行执行；明确 last-write-wins 的字段。
10. workspace trust、全局禁用、managed-only、HTTP URL allowlist。

### 推荐

11. `hook_progress`、`hook_started`、`hook_response` 进度事件。
12. `async`、`asyncRewake`、`asyncTimeout`。
13. 来源分层：user / project / local / policy / plugin / session / builtin。
14. exec form 的逐元素占位符替换；不要先拼 shell。
15. `updatedToolOutput`、`updatedMCPToolOutput`、`classifierContext` 的成对语义。
16. hooks module worker 的 respawn、重入、`.catch` 接管。

### 可延后

17. `prompt` / `agent` / `http` / `mcp_tool` 类型。
18. cloud 转发、MCP cgroup、terminal OSC。
19. 自定义 UI 的 hook attachment 渲染。
